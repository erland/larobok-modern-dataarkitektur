# Terminologi – fastställd redaktionell hemvist

| Term | Kapitel | Arbetsdefinition |
|---|---:|---|
| OLTP/OLAP | 2 | Transaktions- respektive analysbearbetning |
| DWH | 4 | Integrerat analytiskt datalager |
| Data Lake | 5 | Flexibel lagring av data i flera format |
| Lakehouse | 6 | Analytisk arkitektur med lake-lagring och tabell-/bearbetningsförmågor |
| CDC | 9 | Fångst av dataförändringar |
| Dataprodukt | 10 | Förvaltad data med definierat ansvar och konsumentgränssnitt |
| Datakontrakt | 10 | Överenskommelse om struktur, betydelse och villkor |
| Federerad åtkomst | 11 | Åtkomst över flera självständiga datamiljöer |
| Dataplattform | 12 | Sammanhängande gemensamma datatjänster |
| Data Mesh | 13 | Domänorienterat ansvar med gemensam plattform och federerad styrning |
| Data Fabric | 14 | Tvärgående metadataorienterat arkitekturkoncept |
| Lineage | 16 | Spårbarhet för dataursprung och transformationer |
| Portabilitet | 18 | Möjlighet att flytta data och funktionalitet |

| Mottagningszon (stage area) | 4, 9 | Källnära mottagning eller mellanlagring |
| Självbetjäning | 12 | Användning av godkända tjänster utan individuell specialistbeställning |
| Driftplats | 18 | Miljö där funktionalitet körs; skiljs från portabilitet |
| AI-assistent, AI-agent, specialiserad AI-tjänst | 19 | Skilda användnings- och ansvarsmönster |

Skriv Data Warehouse, Data Lake och Lakehouse enligt etablerad kapitelterminologi. Använd datakontrakt, mottagningszon och självbetjäning som huvudtermer. Behåll engelsk term vid introduktion när den underlättar fackläsning. Lineage avser härledning, inte i sig reproducerbarhet. Dataägande avser organisatoriskt ansvar, inte juridisk äganderätt.
